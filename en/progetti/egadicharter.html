Bellavia Egadi Charter

A showcase website for a local charter business running RIB boat tours from Trapani to the Egadi Islands — Favignana and Levanzo. Fast, multilingual and built to turn a visitor into a WhatsApp message in a couple of taps.

The Brief

A small local charter in Trapani needed a website that tourists would actually find and use: clear tours and prices, real photos, and a direct line to the skipper via WhatsApp or phone.

Most visitors are foreign and on a phone, so the site had to be fast, multilingual and indexable — and the owner had to be able to change prices, photos and texts without touching a component.

Goal

More direct bookings via WhatsApp and phone.

Audience

Tourists in Trapani, mostly on mobile, in 7 languages.

Constraint

No backend, no CMS, cheap to host.

Architecture

A React + TypeScript app built with Vite. At build time every route is rendered on the server side in every language and saved as static HTML, then hydrated in the browser — the SEO of a static site with the developer experience of React. The output is served by Nginx in a non-root Docker container, with Caddy in front for automatic HTTPS.

Build pipeline — from content to a page in the browser

Content
src/data + src/i18n
Prices, photos and contacts in typed data files; texts in one dictionary per language.
→
Build
Vite + SSR prerender
Each route × 7 languages rendered to HTML with hreflang, canonical and structured data.
→
Output
Static HTML
Plus sitemap.xml and robots.txt; React hydrates on load for the interactive parts.
→
Serve
Nginx · Caddy
Multi-stage Docker image, Nginx as non-root user, Caddy with Let's Encrypt TLS.

No backend and no database: the only runtime call is to the free Open-Meteo marine API for the sea forecast.

Technologies

React + TypeScript

Why: reusable components (tour cards, slideshow, FAQ) and types that keep data and translations consistent.

How: one Dict type derived from the Italian dictionary: every other language must match it, so a missing translation fails the build.

Payoff: content mistakes are caught before deploy, not by a customer.

Vite + build-time prerendering

Why: a client-only SPA ships an empty HTML shell, which hurts SEO for a business that lives on Google.

How: a server entry renders each route with React Router, a Node script writes the HTML files, the sitemap and robots.txt.

Payoff: every page is indexable in every language, with zero server-side runtime.

CSS Modules + design tokens

Why: scoped styles with no runtime and no framework to learn for whoever edits it next.

How: one .module.css per component, global colours, fonts and spacing as CSS custom properties, self-hosted fonts.

Payoff: a light bundle and styles that never leak between components.

Docker + Nginx + Caddy

Why: deploy on any VPS with one command, HTTPS included.

How: multi-stage build (deps → build → nginx:alpine) running as a non-root user with a health check; Caddy obtains and renews certificates automatically.

Payoff: "git pull + docker compose up" is the whole release process.

Key Features

  • 7 languages — Italian, English, Polish, Spanish, French, German and Chinese, each with its own URL prefix.
  • Data-driven tours — 5 shared and private tours; each one generates its own detail page from a data file.
  • Live sea forecast — wave height, wind and gusts from Open-Meteo, classified as perfect, good or not advised for a RIB.
  • WhatsApp-first booking — sticky price bar on mobile with WhatsApp and call buttons on every tour.
  • SEO — prerendered HTML, hreflang, canonical URLs, sitemap and FAQPage / TouristTrip structured data.
  • Privacy-friendly — Google Maps loads only on click; contact form via mailto or an optional Formspree endpoint.

Challenges & Learnings

SEO for a React app

Solved: prerendered every route at build time instead of adding a Node server. Learned: you can have React and a fully static, crawlable site at the same time.

Seven languages without drift

Solved: typed the dictionaries against the Italian one, so TypeScript flags any missing key. Learned: types are a great tool for content, not just for code.

A site the owner can maintain

Solved: split data, texts and components, and wrote the README for a non-developer: where to change a price, a photo or a phone number. Learned: documentation is part of the product when the client is the one editing it.
